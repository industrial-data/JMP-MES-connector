MES Data Retrieval JMP Add-in — Administrator Guide

Version 3.0 — REST edition (PI Web API / Aspen Process Data REST)

This document describes the administrative tasks required to manage the add-in and its code architecture. It is intended for the system administrator in charge of the add-in. For installation and usage, see the User Guide.

v3.0 in one paragraph: all extraction goes through the historians' REST services — the OLEDB/ODBC/PowerShell paths were removed entirely. PI is served natively by the PI Web API; IP21 keeps the proven SQLplus queries, now wrapped in POSTs to the Aspen Process Data REST service (AtProcessDataREST.dll/SQL). The REST calls are made by a small Python package embedded in the add-in (include/Ressources/python/mes_connector), driven from JSL through JMP's embedded Python. Windows and macOS run the identical code path.

System requirements

  • JMP 18 or later (embedded Python with pandas is used to call the REST services and hand results back as data tables).
  • Network access to the historian REST endpoints (enterprise network or VPN): PI Web API (usually HTTPS, port 443) and/or Aspen Process Data REST (http(s)://<host>/ProcessData/AtProcessDataREST.dll).
  • One-time internet/proxy access on first run so the add-in can install the requests Python package into JMP's isolated Python environment (optionally also keyring, truststore and, on Windows, requests-negotiate-sspi for silent SSO).
Former v2.x requirements that are no longer needed: Aspen SQLplus ODBC driver, PI OLEDB Enterprise, PI Process Book / PI client tools, PowerShell execution rights.

The server list — MES_servers_list.xlsx

The list of servers offered to users is an Excel file downloaded at launch from the URL configured in config.jsl (strPathServerlist). Sheet name: MES_servers_list. Columns:

ColumnRequiredContent
siteno Display name shown to users in the server list (site [type] - server). Not used by the extraction itself. When empty, the server name is displayed instead.
serveryes PI Data Archive server name, or IP21 ADSA data source name (usually the IP21 host name).
TypeyesPI or IP21.
WebAPI_URLyes REST endpoint. Tolerant to missing scheme and trailing slash; a bare host is completed automatically to /piwebapi or /ProcessData/AtProcessDataREST.dll. A server without a URL cannot be queried (there is no driver fallback in v3.0).
PI_AF_Serverno PI Asset Framework server name — reserved for the planned AF attribute search (collapsible element hierarchy; result labels tag (description) [units] {path}).

To administer servers: edit the Excel in the repository (or the location your organization publishes it to) and commit/push — every user picks it up at next launch.

Authentication, credentials & TLS

  • Order of authentication attempts: silent SSO (Windows SSPI/Negotiate, or Kerberos where configured) → credentials stored in the OS credential vault → interactive login dialog.
  • Credential storage: the login dialog's “Remember on this computer” writes the credentials to the Windows Credential Manager / macOS Keychain (via the keyring package) — encrypted at rest by the OS, per user, never stored in files or logs. A stored password that receives a 401 is deleted immediately.
  • Interception safeguards: basic credentials are refused over plain http:// (SSO is still allowed there — Kerberos never transmits the password). TLS certificates are verified by default, against the OS certificate store when the truststore package is present (so corporate CAs work as in a browser).
  • Self-signed plant servers: set int.TLSVerify = 0 in config.jsl — a logged, deliberate opt-out. Prefer installing the proper CA.

Code architecture

The source is organized as one main script plus four folders:

LAUNCH_APPLICATION.jsl      main script: resolves paths, includes dependencies, builds the GUI
config/config.jsl           hard-coded parameters, paths, version
include/                    all JSL dependencies (only *.jsl files are included)
  EXPR_ADD_FILTER.jsl         "Add filter" button logic
  EXPR_DATA_EXTRACTION.jsl    "Run extraction" button logic
  EXPR_PREVIEW.jsl            "Preview" button logic
  ProgressBar.jsl             extraction progress bar
  Attached scripts/           the 4 scripts attached to extracted tables
  Ressources/
    Ressources_REST.jsl       JSL <-> Python bridge (v3.0)
    Ressources_SQL.jsl        IP21 SQLplus queries + query functions (REST transport)
    Ressources_Utilities.jsl  all utility functions incl. f_RunExtraction
    python/mes_connector/     the Python REST layer (see below)
doc/                        this documentation + extracted images (img/)
deployment/                 built .jmpaddin packages

Path resolution: strPath is the add-in home (ADDIN_HOME(MES.Data.Retrieval.OS2.2)). When the add-in is not installed (development), LAUNCH_APPLICATION.jsl falls back to the folder it was run from, validated by locating config/config.jsl. The attached table scripts use the same fallback.

Attached scripts & column properties

The four scripts attached to extracted tables (Update/Refresh, Add tags, Guardband, Additional tools) identify tags through column properties:

  • addin_colname — output column name (also flags TS/TS_UTC)
  • tagname_desc_unit — tag name with unit and description (the column label)
  • tagname — bare tag name
  • tagtype — tag type
Tables extracted with v2.x carry the old attached-script code (with OLEDB references) baked in; users must re-extract to get working v3.0 scripts.

Ressources_SQL.jsl (IP21 SQL over REST)

Contains the IP21 SQLplus queries (prefix __SQL) and the query functions (prefix f_SQL_). Values substituted into queries use the VAR_ prefix. The queries are unchanged from v2.x — only the transport changed: they are POSTed to Aspen's REST service by f_IP21_REST_SQL. PI no longer uses SQL at all; the f_SQL_* functions dispatch PI calls to the Python layer (point search, tag type, preview, extraction).

Extraction method mapping (IP21): Actual → REQUEST 4 on HISTORY(80); Interpolated → REQUEST 6; Step Interpolated → REQUEST 6 with STEPPED = 1; Average → AGGREGATES REQUEST 1. IP21's PERIOD is expressed in tenths of a second.

The Python layer — mes_connector

Located at include/Ressources/python/mes_connector/ and called from Ressources_REST.jsl via JMP's embedded Python (Python Submit/Python Get; pandas DataFrames convert to JMP tables natively). Modules:

FilePurpose
auth.pySessions, SSO, OS-vault credentials, TLS policy, 401 → login-dialog signalling.
pi_webapi.pyPI Web API: uncapped point search, parallel extraction (interpolated / recorded / summary), Step Interpolated = recorded (boundaryType=Outside) forward-filled onto the aligned grid.
ip21_rest.pyPOST SQLplus text to AtProcessDataREST.dll/SQL, XML row set → DataFrame; Browse controller for connection tests.
filters.pyGUI filters → PI filterExpression (simple comparisons, server-side) or pandas masks (Like/Not Like/In).
__init__.pyPublic API used by JSL; URL normalization; chunked extraction session that drives the JSL progress bar.

Read mes_connector/README.md before modifying the Python layer — it documents the JSL↔Python contracts (exact column names the GUI depends on).

Python environment: JMP's Python is isolated with its own site-packages. On first init the add-in installs requests if missing (mandatory) and tries keyring/truststore (optional) plus requests-negotiate-sspi on Windows (optional, enables silent SSO). All installs go through Python Install Packages (JMP's pip).

Debugging

  • Every REST request URL is echoed in the JMP log with its HTTP status (GET https://…/streams/…/interpolated?… -> 200) — the same philosophy as v2.x echoing its PowerShell commands. Open the log with Ctrl+Shift+L.
  • The Python init - OK 3.0.0 | python 3.x | <path> log line confirms the Python layer loaded; an IMPORT_ERROR: line names the missing piece.
  • Aspen errors are returned inside the REST payload and surfaced verbatim (IP21 REST error: …); non-XML answers (proxy/HTML error pages) are reported with the beginning of the payload.
  • Auth loops: a 401 with stored credentials deletes them from the OS vault and re-prompts — check the account/password with the historian team.

Deployment

Package the add-in as a .jmpaddin (zip of the repository content plus the add-in definition) and distribute; see the deployment/ folder for built packages. The add-in ID is MES.Data.Retrieval.OS2.2 — keep it unchanged so existing installations upgrade in place and ADDIN_HOME resolution keeps working. Remember to include the include/Ressources/python/mes_connector folder in the package (plain .py files, no build step).
